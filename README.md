# Reinforcement Learning-Based Auto-Scaling Policy for Multi-Tier Cloud Applications

## What this project does
Uses NASA Kennedy Space Center HTTP request logs to create a real request-rate workload trace. A Gymnasium simulator models a three-tier application (web, application, database). Q-Learning, PPO, and TRPO learn scaling decisions. A threshold-based HPA-style controller is included as a baseline.

**Data integrity note:** NASA logs contain HTTP request timestamps, request paths, status codes, and response sizes. They do not contain cloud CPU, RAM, latency, or VM-cost measurements. Those system metrics are generated by the explicitly documented simulator.

## Quick start (Windows / VS Code)
1. Install Python 3.10 or newer.
2. Open this folder in VS Code.
3. In the terminal:
   ```powershell
   py -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```
4. Download and preprocess NASA logs:
   ```powershell
   python prepare_data.py
   ```
   This downloads the July and August 1995 NASA HTTP traces from the Internet Traffic Archive. If the download fails, download the `.gz` files manually from https://ita.ee.lbl.gov/html/contrib/NASA-HTTP.html and put them in `data/` with their original names, then rerun.
5. Train all methods:
   ```powershell
   python train.py --episodes 25 --ppo-steps 12000 --trpo-steps 12000
   ```
6. Open the dashboard:
   ```powershell
   streamlit run dashboard.py
   ```

## Fast demonstration
For a short laptop demo, first run:
```powershell
python prepare_data.py
python train.py --episodes 5 --ppo-steps 2000 --trpo-steps 2000
streamlit run dashboard.py
```
Use the full training settings for the final experiment if time and hardware allow.

## Project structure
- `prepare_data.py`: downloads, parses, and aggregates NASA logs into one-minute request counts.
- `autoscaling_env.py`: three-tier Gymnasium simulator and reward function.
- `train.py`: tabular Q-Learning, PPO, TRPO, and HPA-style baseline evaluation.
- `dashboard.py`: Streamlit dashboard for results and graphs.
- `results/`: generated metrics and plots.
- `models/`: saved trained policies.

## Metrics
Mean response time (ms), SLA violation rate (%), estimated resource cost (normalized units), average replicas, and reward. All simulated metrics must be described as simulation outputs, not direct NASA measurements.

## Reproducibility
Training is stochastic. Record the command, Python/package versions, trace file used, training steps, and random seed in the report. Do not claim a particular algorithm wins until your generated `results/summary.csv` confirms it.
